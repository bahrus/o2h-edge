## Claude's Implementation Notes

The worker is scaffolded in TypeScript, builds, and passes its tests locally under `wrangler dev`. **Nothing is deployed:** `wrangler login` and the first deploy need your account.

### How it was set up

**By hand rather than with C3** (`npm create cloudflare`): C3 wants an empty folder, and this repo already had its git history, README and LICENSE. The result is what C3 would produce for a TypeScript Worker:

| File | What |
|---|---|
| `package.json` | Scripts: `dev`, `deploy`, `test`, `check`, `types`. Dev dependencies: `wrangler` 4.152, `typescript`. Dependencies: `o2h` and `assign-gingerly`, as `file:` links to the sibling repos. |
| `wrangler.jsonc` | `main: src/index.ts`, and a compatibility date. The **`RECORDS` KV namespace has no id:** wrangler creates it on the first deploy. The **`LIMITER` rate limit** is 60 a minute. The **vars** are the guards' settings. The **aliases** are explained below. |
| `tsconfig.json`, `worker-configuration.d.ts` | The TypeScript setup. The `Env` type is generated by `wrangler types --strict-vars=false`, so vars are typed as strings, not their literal values. |
| `src/index.ts` | The router: `PUT /records/<key>`, `GET /render?api=…&config=…`, `GET /`, CORS, and the rate limit |
| `src/guards.ts` | Which API origins a host may call (the sandbox and `DOMAIN_ALLOWLIST`), the target rules, and the guarded `fetch` (GET only, only `Accept` sent, timeout, JSON only, size cap) |
| `src/records.ts` | KV records keyed by the **hash of their content** (as `prepareO2HRecord` computes it). The worker recomputes the hash before storing, so a record can be added by anyone but changed by no one. |
| `test/edge.test.mjs`, `test/guards.test.ts` | Tests (below) |
| `README.md` | Endpoints, guards, developing, deploying |
| `.gitignore` | Adds `.wrangler/` (local state) and `.dev.vars*` (local secrets) |

### How a render works

The page calls `/render?api=<API URL>&config=<key>`. The worker:
1. checks the API URL against the requesting host's allowlist;
2. builds a request to the API, marked with the record's key;
3. hands it to **o2h's shared core** (`handleO2HRequest`), with a KV lookup and the guarded `fetch`.

From there it's exactly the service worker's behavior: forward without the marker, render with `embed`, fall back to the JSON with `X-O2H-Error`. Lost code is left pending, and data pipes run. **The query parameter instead of a header** keeps the request "simple" in CORS terms, so a cross-origin page triggers no preflight for rendering. Storing a record (a `PUT` with JSON) does get a preflight, which the worker answers.

### Two workspace wrinkles

1. **Bundling:** o2h's own `node_modules` still holds the older assign-gingerly (without `pipes/dataPipes.js`), and the bundler resolves o2h's imports from there. A single `alias` for the package didn't work, because **wrangler's aliases match whole import specifiers, not subpaths** (I tried both relative and absolute forms). So `wrangler.jsonc` aliases each of the six assign-gingerly modules o2h imports to the sibling repo. These go away once o2h-edge depends on published versions.
2. **Type-checking:** o2h's TypeScript sources import assign-gingerly's DOM-side modules, which don't type-check against the Workers runtime types. So `tsconfig.json` maps `o2h/worker/core.js` to a small declaration file, `src/types/o2h-worker-core.d.ts`, covering the four things the worker uses. **The better fix is in o2h:** emitting `.d.ts` files for its `worker/` modules. Then this file goes away. Worth doing when o2h is next published.

### Tests

**`npm test`** (13 tests, all passing, twice in a row; nothing is left running afterwards):
- **`test/edge.test.mjs`:** starts a stand-in API on port 8799 and the worker under `wrangler dev` on 8788, with fresh local state each run. Records are made with o2h's real `prepareO2HRecord`. It checks:
  - **records:** stored under their content's key; refused when the key doesn't match or isn't a key; `PUT` only;
  - **render:** the exact HTML, the embedded JSON (with `</script>` in the data) round-tripping, `text/html`, and CORS;
  - **lost code:** a function pipe leaves `<h2 data-pending>`;
  - **a missing record:** the JSON back, with `X-O2H-Error` exposed to pages;
  - **guards:**
    - non-JSON is refused (415), oversized responses (413), slow ones (504), and API errors are passed on (404);
    - the caller's `Cookie`, `Authorization`, custom headers and the record header **don't reach the API**; only `Accept: application/json` does;
    - bad requests get 400 / 403 / 404, and the `OPTIONS` preflight is answered;
    - the per-IP rate limit returns 429.
- **`test/guards.test.ts`** (Node, which strips the types): the sandbox hosts, the sandbox's off switch, allowlists per host, `https` only, and no IP literals or localhost targets, except in development with `ALLOW_LOCAL_UPSTREAM`.

**One gotcha found on the way:** the local rate limiter's count is persisted with the rest of the local state. The rate-limit test (70 requests) used up the minute, and the next run began with 429s. The tests now delete their local state first.

**`npm run check`** type-checks cleanly. **`wrangler deploy --dry-run`** bundles it: 231 KB, 50 KB gzipped (well within Workers' limits), with both bindings recognized.
